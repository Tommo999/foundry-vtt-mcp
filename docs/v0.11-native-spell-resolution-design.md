# v0.11 native spell resolution design

Main-agent design, based on exact PF2e tag `pf2e-8.7.0`. This document describes planned scope; implementation and live results must be recorded separately.

## Primary API evidence

- [Spell document](https://github.com/foundryvtt/pf2e/blob/pf2e-8.7.0/src/module/item/spell/document.ts): `rollAttack(event, attackNumber, context)`, `getDamage({ target, skipDialog, messageMode })`, `rollDamage(event, mapIncreases)`, `loadVariant({castRank})`, `isVariant`/`original` and native origin rank.
- [Statistic](https://github.com/foundryvtt/pf2e/blob/pf2e-8.7.0/src/module/system/statistic/statistic.ts): explicit roller `token`, Actor-valued `target` and `origin`, native contextual statistics/DC, callbacks and extra roll options/identifier.
- [Native damage roller](https://github.com/foundryvtt/pf2e/blob/pf2e-8.7.0/src/module/system/damage/damage.ts): evaluated native damage, context/target/origin flags, speaker, visibility and `pf2e.damageRoll` hooks.
- [Exposed API](https://github.com/foundryvtt/pf2e/blob/pf2e-8.7.0/src/scripts/set-game-pf2e.ts): internal `DamagePF2e` is not directly exposed.
- [Chat message](https://github.com/foundryvtt/pf2e/blob/pf2e-8.7.0/src/module/chat-message/document.ts): current native message membership and flags remain authoritative.

Local exact-version evidence copies are `/tmp/v09-src_module_item_spell_document.ts` and `/tmp/v011-src_module_*`; they are research artifacts, not installation inputs.

## Contract

Add four tools (expected total 60): `pf2e_inspect_spell_resolution` and approved native `pf2e_roll_spell_attack`, `pf2e_roll_spell_save`, `pf2e_roll_spell_damage`. Preview selects action (`attack`, `save`, `damage`), exact confirmed actual-cast message UUID, explicit same-scene caster/target tokens, native message mode and attack number where applicable. Execution requires the identical selection, expiring session-bound intent/review token and exact nullable encounter snapshot.

Use only an actual-cast message from the bridge's confirmed spell-cast ledger whose card UUID/cast ID, owned entry/spell and native cast rank agree. Require the native `origin.castRank` value; do not guess from the current base spell rank when it is missing. Reject arbitrary chat cards, non-cast cards, unresolved ledger outcomes and forged/stale document relationships. Do not require remaining slots after the already-confirmed cast. Bind Actor/Item/token/card source and derived native facts, identities, session/world/GM, target state and applicable combat snapshot to preview. Recheck after hashing and before every native mutation. No implicit caster/target selection or caller-supplied DC, formula, raw flags, arbitrary native method, overlay IDs or free-spend bypass.

An independent durable bounded spell-resolution ledger reserves a semantic operation key (cast card, action, target and attack number where relevant) before the native roll. Confirmed history blocks accidental repeats; reserved/uncertain outcomes block blind retries and survive reload. Capacity fails closed without eviction. No clear/refund/retry override. Use one terminal persistence attempt and report observed facts on lost acknowledgement. Native results are not replayed to repair audit state.

## Native calls

Attacks use the native owned/rank-specific spell `rollAttack` and native statistics, with explicit caster token, explicit target Actor, mode, skip-dialog, native callback and a bounded per-intent roll option/identifier for correlation. PF2e selects the target token from the Actor's active tokens. Refuse when that native token cannot be proven to equal the requested token; linked duplicates cannot be guessed. Pass no caller event or modifiers.

Saves use the target's native Fortitude/Reflex/Will statistic selected from the spell's own defense. Derive the native current spell DC from the caster entry/statistic and rank-specific spell; bind it to preview. Supply explicit target token, caster Actor origin and the native spell item/traits so PF2e can apply native contextual rules. Refuse ambiguous native caster-origin token selection. One target per reviewed operation; no mass saves or automatic damage scaling.

Damage uses PF2e's native rank-specific spell and final native `rollDamage` pipeline, preserving formula generation, hooks and message flags. Since that method reads global targets, create an ephemeral native heightened/base spell representation, verify original/parent/UUID/rank and wrap only that ephemeral object's `getDamage` to force the explicit target, mode and skip-dialog before forwarding to native `getDamage`. Do not change owned document methods or global targets. Ensure native variant recursion cannot replace the scoped ephemeral instance. Require the native resolved context origin token/Actor to already match the explicit caster; do not rewrite a different token after token-sensitive native modifier preparation. Attach a namespaced correlation option without fabricating PF2e origin facts. Revalidate reviewed context after native preparation awaits, immediately before returning control to native rolling.

The initial damage action rolls native base damage. It does not infer success/critical/save multipliers, choose alternate spell forms, spend resources or apply HP. PF2e's `getDamage` ignores target context for non-attack spells; such base damage must be labelled target-independent and must not claim target-specific modifiers. Restrict to supported damage-only base shapes; refuse ambiguous healing/damage or alternate workflows. Explicit target remains review context for subsequent separate damage inspection/application. Native unsupported shapes fail explicitly rather than simulate rules.

## Confirmation and limits

Correlate actual world messages using native callbacks/hooks plus the per-intent native roll option/identifier. Require evaluated finite native roll type, exact spell origin/rank, explicit speaker, native target where applicable, visibility and preserved native flags. Add only bounded bridge metadata linking the operation/card/intent; never fake native PF2e flags. Re-resolve and revalidate context after awaits; native hook/resource/chat uncertainty is partial and never automatically retried. Preserve persistent damage protections and strike ammunition restrictions.

No action-economy tracking, automatic effects/templates, resource consumption, target-save scaling, HP changes, recovery, duration/time advance, counteracts, reactions or off-turn bypasses are added by roll tools. Existing `pf2e_inspect_damage_application` and separately approved `pf2e_apply_damage` remain the HP workflow. Live matching-build tests and exact supported exclusions must be recorded before compatibility claims.
