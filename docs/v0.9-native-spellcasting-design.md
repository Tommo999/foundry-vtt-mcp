## Native behavior relevant to implementation

- Regular owned spellcasting entries are available through the Actor's spellcasting collection; ephemeral item/trick/ritual entries are distinguishable. Entry categories include prepared, spontaneous, innate and focus; flexible prepared entries use a slot pool rather than ordinary individual prepared-slot expenditure.
- `entry.spells.getSpellData()` supplies native groups, active spells, ranks, prepared-slot positions, signature/virtual heightened options and resource availability. Use these data to enumerate legal supported selections rather than inventing heightening or repertoire rules. Empty prepared positions must retain their original indices.
- `entry.cast()` normally consumes resources and posts a spell card, but returns no authoritative result. Consumption can refuse without throwing. A resolved promise therefore does not prove a cast succeeded.
- `entry.consume(spell, rank, slotId)` is the native consumption operation used by `entry.cast()` and returns an authoritative boolean. Use this API directly, then the native actual-cast card API, so a native refusal cannot be mistaken for success. Prepared slots are expended by the collection API, spontaneous/flexible slots by the entry, innate uses by the owned spell, and focus by the Actor. Cantrips with no focus cost do not expend resources. Also confirm the expected native resource transition; never write resource fields directly.
- Native prepared consumption accepts an existing explicit slot index without independently proving it contains the requested spell. The bridge must validate exact slot-to-spell membership before invoking it.
- Native `spell.toMessage()` supports an uncreated native card (`create: false`) and the actual-cast marker. Its base implementation can choose the first active token for a linked Actor; explicit caster context must replace that speaker before final native ChatMessage creation. Preserve PF2e-generated flags/content. Bind the selected native message mode (`public`, `gm`, `blind` or `self`, default `gm`) to the inspected intent and pass it as `mode` to `spell.toMessage()`. The returned source already encodes visibility. Follow the spell override's own creation path, `ChatMessage.create(messageSource, { renderSheet: false })`, preserving the full mode-applied source rather than reconstructing or reapplying visibility.
- Native casting posts a card and consumes the selected resource. It does not automatically execute every spell's attack/save, template, effect or HP application. This release should expose that same bounded operation with explicit recorded targets, without altering the GM's controlled tokens or current target selection.
- The exact-version [spell constants](https://github.com/foundryvtt/pf2e/blob/pf2e-8.7.0/src/module/item/spell/values.ts) define the actual-cast origin roll option as `origin:action:slug:cast-a-spell`. Assert that native `actualCast: true` creates/preserves it in message flags; do not invent a replacement flag and treat that as native cast confirmation.
- PF2e 8.7.0's own at-will getter explicitly leaves innate constant/at-will handling unfinished. Do not simulate unlimited innate uses or pretend that the native API confirms them; show an unsupported reason when the native data/API cannot represent a confirmed supported cast.

## Tool surface

The current design adds four PF2e tools after v0.8.2's `end_encounter` (expected total: 56 tools):

1. `pf2e_inspect_spellcasting`: bounded entry/spell/cast-option inspection for a world Actor or explicit scene token. Return exact entry/spell UUIDs, native ranks, prepared-slot positions, entry category/tradition and supported/available status with reasons.
2. `pf2e_inspect_resources`: bounded native focus, slot/innate-use and other exposed resource summaries; preserve zeros and distinguish missing data. Include actor-specific blocked/uncertain spell-cast state without exposing an unrestricted ledger mutation API.
3. `pf2e_inspect_spell_cast`: prepare one explicit caster token/entry/spell/rank/slot/target selection. Return resource cost/before state, supported native behavior, expected combat state when applicable, a unique short-lived cast intent ID and a fingerprint bound to the exact reviewed selection/state.
4. `pf2e_cast_spell`: apply that inspected intent through native casting/resource and chat APIs after approval. Require the same selections, intent ID and fingerprint; no caller-supplied free-cast flag, arbitrary resource field, deletion option, raw rule object or arbitrary native method name.

Ordinary native prepared, flexible prepared, spontaneous/signature, focus, cantrip and finite-use innate paths remain in scope where confirmed by the exact-version API. Unsupported rituals, item/wand/staff/trick entries, consumable activation, alternate/amped variants and reaction/off-turn execution must be identified explicitly; do not silently substitute another action. Casting does not implement automatic spell HP/effects, action-economy bookkeeping, templates or persistent ticks.

## Input and inspection contract

- The two broad read tools accept `targetUuid` (root world Actor or explicit world Scene Token), optional `entryUuid` where applicable, and bounded pagination (`offset >= 0`, `1 <= limit <= 100`, default 25). Return total/offset/limit/hasMore and null for genuinely absent resource values; zero is a real value. Restrict native spellcasting to character/NPC Actors. Other Actor types should receive an explicit unsupported response.
- Spellcasting inspection pages native cast options, with entry summaries for returned options and a bounded entry listing so empty or unsupported entries remain discoverable. Preserve prepared-slot indices including holes. Report spell UUID/name, entry UUID/category/tradition, native prepared statistic DC/attack modifier where available (`statistic.dc.value` / `statistic.check.mod`, missing as null), native cast rank, nullable prepared slot index, signature/virtual flags, resource kind/cost, availability and unsupported reason. Bounded spell facts may include native casting time, range, target, requirements and material-cost text; these facts do not imply automated target resolution or material spending. Summaries must not serialize full Actor/Item sources or rule objects.
- Resource inspection exposes native focus and hero-point summaries where present; bounded slot/innate-use records; and observed owned-item `uses`/`system.frequency` summaries where present. These are factual reads, not an inferred recovery schedule or activation API. Label unsupported/missing shapes rather than inventing unlimited uses. Item/resource details need bounded output even on large Actors.
- Cast preview requires `casterTokenUuid`, `entryUuid`, `spellUuid`, native `rank` (1–10, including autoheightened cantrip rank), nullable `slotId`, a unique list of at most 20 explicit same-scene `targetTokenUuids` (default empty), and native `messageMode` (default `gm`). There is no implicit caster token. The preview returns the exact selection, expected combat snapshot (null outside combat), resource facts, expiry, `castId` and `reviewToken`.
- Keep the native slot-group number distinct from the displayed/computed cast rank. Prepared cantrips use group `cantrips` / slot number 0 while their card rank is autoheightened; a prepared cantrip's explicit slot index must still identify its actual prepared position. This also applies to flexible prepared cantrip lists. Flexible non-cantrip and spontaneous casts use a rank pool and require null `slotId`. Derive group/rank from the exact native option; do not let an arbitrary displayed rank select a different prepared list.
- Pass the derived native group/slot number to `entry.consume()` and the bound computed cast rank to native card creation. They can differ for cantrips and automatically heightened focus spells. Reject ambiguous/inconsistent native selections instead of choosing the first matching slot or silently substituting another resource group.
- High-level NPC focus groups are an important exact-version edge: `getSpellData()` uses `ceil(actor.level / 2)` for the focus group ID without clamping, while `spell.rank` clamps the actual rank to 1–10. A level-25 NPC can therefore expose group 13 with actual rank 10. Preserve that native group as a nonnegative safe integer in internal resource/audit facts; do not reject it or create a rank-13 card. Focus consumption uses the Actor pool before the native ranked-slot branch.
- Cast execution requires the same selection plus `castId`, `reviewToken` and the exact nullable expected combat snapshot returned by preview. Targets are recorded context only: the cast does not roll their saves or resolve effects. A caller cannot change targets, visibility, slot or rank after inspection. Unknown/expired/reloaded/cross-session intents fail before mutation.
- Native cast-option membership is necessary but not sufficient: independently verify owned Actor/entry/spell identity, collection membership, prepared slot membership and expended state, positive native resource availability, supported casting time and absence of unsupported overlays/parent-item workflows. Return an actionable unsupported reason for reaction/free-action or alternate workflows instead of guessing action timing. Exploration casting outside combat remains supported; do not require a combat to exist.
- Base spells may expose alternative overlays without selecting one. Do not reject their ordinary native base cast solely because alternate options exist; reject a selected variant/original/parent-item workflow that this contract cannot represent. Native one-to-three-action base cards can be posted without pretending to track action spending. Multi-round/minute casting in combat requires a future workflow and must be reported unsupported; outside combat a native exploration casting time may be reported and the ordinary card posted without simulating elapsed world time.
- A started current combat applies to casting in its scene. Bind preview to its UUID/round/turn/combatant and require the explicit caster token to be the current combatant. A started combat on another scene is not permission to infer a caster or silently advance either encounter. Re-evaluate the applicable combat during execution so a newly started/switched encounter invalidates the earlier preview.
- The module bridge context supplies its current connection session ID to these handlers, in addition to world and GM identity. Expose it through a getter (or equivalent current-value accessor), including the PF2e context wrapper, so revalidation after an await observes a changed pairing rather than a captured old ID. Require a nonempty session for preview/execution; broad inspection can remain available without intent creation. Reads do not need write approval. Preview creates only bounded expiring local intent state (maximum 500 intents, five-minute lifetime); no world setting or chat mutation occurs until approved execution.

## Persistent outcome records

Register a separate restricted world setting, `spellCasts`, with `{ version: 1, entries: {} }`. Keep at most 5000 records without eviction. Validate record shape and fail closed on unreadable/malformed settings; a missing value may initialize the documented default, but a settings read exception is not an empty ledger. Serialize all spell ledger updates through a world-level lock, and acquire the existing combat lock inside it for a combat cast. This prevents two different casters from overwriting one another's reservations. A confirmed record blocks the same intent; any reserved/uncertain record also blocks new intents for that Actor until manually reconciled. Do not expose a clear, force, refund or retry override. Preserve the separate damage ledger without edits.

Store bounded primitive identifiers, inspected fingerprint, world/Actor/caster/entry/spell/rank/slot, timestamps, resource before/after, status (`reserved`, `confirmed`, `uncertain`) and resulting chat UUID. Prove reservation persistence before consumption. If ledger confirmation cannot be established after native work, report the known resource/chat results and observed audit state. Every persisted reserved/uncertain record must continue to block new intents for that Actor; do not erase it to permit a retry. If native consumption explicitly returns false, post no card and do not claim success; retain a blocked record when native side effects cannot be ruled out. Successful cantrips still require a new preview for each intentional repeated cast.

Do not compensate for a failed terminal audit write by restoring an older reservation or erasing known resource/chat facts. Make one terminal persistence attempt, then inspect/report the observed status without another corrective write. Failure before commit naturally leaves the reservation blocking. A commit followed by lost acknowledgement may instead leave a confirmed or uncertain record; report that observed state honestly. Do not claim the Actor is blocked when the observed record is confirmed, and do not replay native gameplay to recover an audit response. An uncertain gameplay operation can receive one uncertain-outcome finalization attempt; a failed confirmed finalization must not trigger a second automatic finalization.

## Guarded native sequence

1. Validate PF2e availability, world/scene/Actor identity, caster and target token membership, owned regular entry/spell identity and native cast-option membership. For a current encounter, require the current combatant and exact expected tracker state. A root Actor with multiple tokens must never cause an implicit caster selection.
2. Inspection may create bounded expiring in-memory intent state; it must not change Foundry documents, consume resources or post chat. Bind the intent to world/user/bridge session, explicit selection and the resource/entry/spell/native-option snapshot. A fresh intent is required for a deliberately repeated free cantrip.
3. Under the cast/Actor lock and combat lock where applicable, revalidate identity, authorization, resource snapshot and current turn. Reserve the unique intent durably in a separate GM-restricted spell-cast ledger before the native operation. Do not alter the existing damage ledger.
4. Invoke `entry.consume(spell, rank, slotId)` after the durable reservation. A false result must produce no cast card and no successful-cast result; retain an uncertain record if the outcome cannot be proved safe. Verify the native resource transition. Build the native actual-cast chat card without creating it, set the explicit native speaker and bounded bridge intent/target metadata, then recheck authorization before native ChatMessage creation using the inspected message mode. Do not change global targeting to force a native context.
5. Confirm native message identity and resource state before marking the intent confirmed. Preserve native flags and hooks. A native error, rejected/unconfirmed resource transition, session change or chat uncertainty after reservation must report partial/uncertain state and prohibit blind retries. Never refund resources or clear a reservation automatically.
6. A successful intent cannot be reused. An unresolved reservation for the same Actor blocks a new differently named intent from bypassing reconciliation. Bounded durable history must reject capacity overflow rather than evict duplicate/uncertain protection. This serializes bridge-mediated operations, not manual changes or a distributed transaction.

## Validation requirements

Use source-shaped native groups and callbacks, not mocks that always report success. Cover prepared empty/expended/wrong-slot cases, signatures and heightening, flexible pool consumption, innate exhaustion, focus cost, cantrips, native consumption refusal returning false, resource/chat interruption, stale selection/resources/turn, duplicate intent, cross-session reuse, unknown ledger state/capacity and no world mutation on reads. Confirm explicit speakers, message modes and targets without changing global controlled/targeted tokens. Retain existing damage, inventory, strike and encounter regressions.

Live checks require the matching built module and companion actually loaded, isolated caster fixtures and verification of native resource/chat outcomes. Do not infer completion from unit tests or a manifest on disk alone; record unavailable checks explicitly.
