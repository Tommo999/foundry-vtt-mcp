# v0.13 reviewed native spell effects and duration visibility

Main-agent plan for the active sequential goal, based on exact PF2e `pf2e-8.7.0` sources. Implement only after v0.11 and v0.12 are reviewed and integrated. This is not acceptance evidence.

## Scope and operator contract

Add an inspected/approved application workflow for an explicit operator-selected native compendium effect or condition outcome, tied to a confirmed bridge actual-cast card and one explicit same-scene target token. Do not infer a spell-to-effect mapping from names, descriptions or chat text, infer degree-of-success effects, synthesize effects or parse rules text. Clearly identify the selection as the GM's choice, not verified automatic spell-rule mapping.

Proposed tools: `pf2e_inspect_spell_effect` (read-only preview), `pf2e_apply_spell_effect` (approved native write), and `pf2e_inspect_spell_durations` (bounded read-only native state/reminders). Reuse the v0.11 confirmed source-card validation, native origin/rank/entry/speaker/world identity and explicit target binding. Selection includes either an exact installed PF2e compendium root effect UUID, or an explicit native condition slug and nullable exact value. No user document payload, formula, raw flags, duration override, origin override, persistent-damage simulation or arbitrary method name.

Use expiring session/world/GM-bound local intents and source/target/derived native fingerprints. Synchronously recheck after the final hash await, lock waits and before each native mutation; revalidate after native awaits and report partial outcomes. Do not consume spell resources/actions again or apply HP. Preserve TLS, approval-by-default and session automatic-write behavior.

### Settled implementation contract

Preview takes the exact `castMessageUuid`, `casterTokenUuid`, `targetTokenUuid` and a strict choice: either `{kind: "effect", uuid: <compendium UUID>}` or `{kind: "condition", slug, value: <integer 1–100 or null>}`. Null is for a native unvalued condition; preview rejects a shape that disagrees with the native condition. The result includes the exact selection, an expiring `applicationId`/`reviewToken`, expected native operation/result and nullable `expectedCombat`. Application repeats that selection and exact review/combat values. No caller-supplied source data or duration is accepted. The final discovery contract is 66 tools.

Reuse the confirmed-cast and explicit-token rules of spell resolution: recorded cast targets constrain the choice; an empty recorded list permits an explicit same-scene target. In valid started same-scene combat the caster must be current, and execution rechecks the captured tracker state. Duration inspection does not impose an on-turn requirement.

Duration inspection requires an explicit `targetUuid` (owned world Actor or scene token), with bounded offset/limit (maximum 50), optional sustained-only and include-expired filters. Return native effects/conditions, nullable duration/remaining/expiry/start facts, and bridge cast/application links when present. This also covers native effects created outside this workflow; missing bridge linkage stays null. The Bridge view requires explicit target selection and uses the same read handler.

## Native effects and provenance

PF2e 8.7 AbstractEffect context schema supports:

- `origin`: actual Actor UUID, nullable Token UUID, nullable Item UUID, nullable native spellcasting attribute/tradition data, native rollOptions array;
- nullable `target`: actual Actor/Token UUIDs;
- nullable `roll`: native total and degree, which this workflow must leave null rather than fabricate.

Copy the chosen compendium effect through the system's native import API and create it through native Actor embedded Item APIs. Keep its rules, duration, value and native grant behavior. Populate only schema-supported truthful origin/target context from the confirmed caster/spell and chosen target, preserving supported source context fields; spellcasting data can remain null unless obtained from actual native facts. Use native confirmed cast roll options only. Native AbstractEffect preCreate infers `fromSpell` from the real spell origin; do not force fake PF2e flags.

Native Effect preCreate initializes `system.start` from current world time and origin/current initiative. Do not simulate start/expiry, change world time or extend duration. Preserve source duration mechanics and let native construction/hooks normalize them. Confirm the created effect is a current owned world Item with the expected source/provenance and bounded own bridge audit linkage. Native grants may create additional items; inspect and report bounded actual results rather than claiming only one document was touched. No compensating deletions on failure.

## Native conditions

Use `ConditionManager.getCondition` to validate the slug and valued/unvalued shape; reject persistent damage and unsupported specialized workflows explicitly. Native `Actor.increaseCondition(slug,{value,max})` creates absent valued conditions, and `ConditionManager.updateConditionValue` updates an identified existing condition. Native creation does not accept spell context, so record cast linkage in bridge audit data and do not overwrite native condition provenance.

An existing exact requested value (or existing unvalued condition) is an explicit already-satisfied no-op; do not call increase and accidentally increment it. Preview identifies the exact current condition and grant/lock/read-only restrictions. This application workflow never decreases/removes a condition and rejects zero; larger native values must not be lowered as an incidental spell outcome. Any increase uses the exact previewed editable condition and native API with native caps validated/read back. Preserve native merge/deactivation/grant rules and existing origins. Where no supported native operation can confirm the requested outcome, refuse rather than create raw condition Items or patch arbitrary context.

## Durable duplicate and recovery semantics

Add a separate restricted versioned bounded world spell-effect outcome ledger (5000 records, no eviction). Reserve/read back before native work, use shared spell-audit serialization, and retain confirmed/reserved/uncertain semantic operation keys across reload. Key effect outcomes by cast card/target/effect UUID and condition outcomes by cast card/target/slug (not intent or visibility/value changes), preventing a fresh intent from replaying an uncertain application. Native no-op outcomes are auditable without altering condition provenance.

One terminal persistence attempt; on lost acknowledgement observe/report stored state and known created/updated UUIDs, never replay/refund/delete to repair the audit. Extend v0.12 bounded history/evidence inspection and append-only reconciliation to the new ledger using concrete current native Item/condition evidence; do not erase the original record or reopen its semantic key.

Use the same acyclic lock order as resolution: durable reserve before combat, native work under combat with no audit writes, release combat before finalization. The effect ledger and reconciliation setting share audit serialization. Effect recovery accepts confirmed-observed evidence only, never absence-based not-performed evidence. It requires the exact current target-owned Item, selected compendium/native condition identity and stored operation/provenance/known outcome facts. Conditions retain native provenance, so insufficient durable linkage remains unresolved rather than adding cast flags after the fact. Accepted overlays change effective history only and never reopen the application key.

## Durations and advisory sustain reminders

Read native `remainingDuration`, `isExpired`/`system.expired`, source `duration.value/unit/expiry/sustained` and native start/initiative facts. Missing facts remain unknown; unlimited duration is labelled from native unit, not invented finite seconds. PF2e combat/world-time hooks remain authoritative for expiry.

There is no native sustain action exposed in the inspected 8.7 Effect source. Provide advisory sustained-effect reminders with caster/target/effect/card links and current native remaining/expiry status. Do not mark a sustain action spent, extend duration, advance time/turns, recover resources, delete effects or schedule persistent mutations. The GM Bridge window gets a bounded refreshable active-effect/duration/sustain section; any refresh or combat-change observation is read-only. Full pagination/filtering remains available through the duration tool.
