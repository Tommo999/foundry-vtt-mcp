# Connection and access security

The MCP companion binds to loopback by default. Its browser bridge uses HTTPS/WSS with a trusted localhost certificate; certificate checks must remain enabled. Configure only the expected Foundry HTTPS origin. The companion accepts one paired GM browser and pins requests to that browser's current world and user session.

The pairing token grants access to the local bridge. Keep it private and rotate it if exposed. Keep TLS private keys and companion configuration out of source control. Do not expose the loopback companion port through the router or reverse proxy.

The module checks that the connected user is a GM and enforces the approval setting again when each write executes. Approval is the default. Automatic writes apply only until disconnect or world change. Pending approvals expire after five minutes. When a connection fails during a write, its result may be unknown: check Foundry before asking the agent to try again. The companion must not replay that write automatically.

The tools expose bounded document preparation and explicitly approved native Foundry operations. They do not expose arbitrary JavaScript or macros, permission changes, or general world-document deletion. Scoped operations can remove a selected condition, effect, inventory item or combatant; approved encounter controls can roll initiative, start a combat, advance a turn, and post a selected primary strike or damage roll. Native PF2e and module rule hooks may run as part of a roll or damage application; the tool does not promise to suppress their effects. The strike adapter disables ammunition consumption where PF2e supports it and rejects consumable-trait strikes. Damage application requires inspection and GM approval by default. A GM-restricted world setting stores duplicate-prevention records; it is persisted state, not a confidential secret store or distributed lock. Uncertain reservations block retries until manually reconciled against chat and Actor state. These tools do not cast spells. Foundry's own validation and permissions remain authoritative.
