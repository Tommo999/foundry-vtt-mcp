# v0.12 spell history and evidence-bound recovery design

Main-agent scope for the active v0.11–v0.13 goal. Implementation follows acceptance of v0.11; this document is a plan, not completed validation.

## Operator workflow and contract

Add three tools: `pf2e_inspect_spell_history`, `pf2e_inspect_spell_reconciliation`, and approved `pf2e_reconcile_spell_audit`. History is paginated, bounded and filterable by Actor, ledger kind and original/effective status. Return primitive identifiers, timestamps, operation, owned spell/target references, resource/roll outcomes, source/effective status and evidence/message links; never expose session IDs, review tokens, pairing/configuration or full Actor/chat sources.

The Foundry Bridge window gets a bounded read-only Spell audit section with refresh/details and reconciliation preview. Any reconcile action uses the same handler, exact expiring review selection and existing write-approval/session path as MCP; no second privileged mutation implementation. Preserve session automatic writes and approval-by-default.

Inspection identifies one reserved/uncertain source record and reports current evidence, missing/contradictory facts and whether confirmed-observed or strictly evidenced refused-unchanged reconciliation is available. It creates only local expiring bounded review state. Execution requires the exact record/evidence fingerprint and current world/GM/session; revalidate after hashing, lock waits and immediately before the one append write. Refuse stale/cross-world/changed evidence and unknown or expired reviews.

## Append-only audit and effective state

Use a separate restricted world `spellReconciliations` setting, versioned, bounded at 5000 records with no eviction. Store a unique reconciliation ID, exact source kind/ID and source fingerprint, evidence/version/message/resource/roll identifiers, GM/world, timestamp and a bounded fixed decision/rationale. Source cast/resolution records stay unchanged, including original status and terminal facts. No deletion, correction of old entries, forced status, arbitrary note payload, refunds or native replay.

A validated confirmed-observed or refused-unchanged overlay can remove an old unresolved cast from the Actor-wide blocker for a genuinely fresh cast. It NEVER permits reuse of the original castId or resolution semantic operation key. History and Actor summaries show originalStatus and effectiveStatus plus the reconciliation reference. Unknown/malformed reconciliation data fails closed; the ledger cannot silently be treated as empty. Share world audit serialization for cast reservation/blocker reads and reconciliation append, and recheck source evidence under that lock. Preserve separate damage-application records without edits.

Persist a bounded nonsecret source projection and an immutable source fingerprint; do not duplicate session IDs or review tokens into reconciliation history. Bind overlays to that exact projection, source kind/ID, world and Actor. An accepted overlay is evidence at approval time: later legitimate resource spending does not invalidate it. History supports separate original-status and effective-status filters.

Lock order must remain acyclic. Casts may hold the audit lock while waiting for combat. Resolution reserves under the audit lock before combat, performs native work under combat without audit writes, releases combat, then attempts one terminal audit write. Reconciliation never invokes native gameplay or acquires combat. Distinguish absent, observed and unreadable/malformed append readback explicitly; unknown is not known-absent.

## Evidence predicates

For new casts, attach bounded versioned resource evidence to the native cast card after native consume=true and the checked expected transition: exact castId/world/Actor/caster/entry/spell/rank/slot, immutable resourceBefore and observed resourceAfter, nativeConsumed=true and the reviewed fingerprint. This is an observed proof point, not a transaction guarantee; native hooks and later manual changes remain authoritative. Never manufacture PF2e native flags.

Confirmed cast reconciliation requires one exact current-world native actual-cast card, matching castId/ledger origin, entry/spell/rank, explicit speaker, visibility/targets and bridge metadata, plus stored terminal resource evidence or the new card evidence matching the reservation's immutable before state and expected native transition. Resolve current owned identities and require current native resource facts to remain consistent with the accepted after evidence. Bind every observation to inspection. Legacy reserved records without sufficient durable resource evidence remain unresolved; current resource state alone cannot establish historical consumption.

When a resource-evidence block is present on a card, it must match exactly; contradictory or malformed card evidence cannot fall back to ledger facts. Native-created cards must retain the prepared resource proof after creation hooks. Legacy cards without the block can use the separately identified durable terminal-ledger evidence basis only when its native-consumed and transition facts are sufficient.

Confirmed roll reconciliation requires one exact current-world native evaluated message with the source resolution ID/card/action/target marker, expected native origin/rank/speaker/visibility/context/type and matching finite native roll facts. Stored outcome facts, if present, must agree. Source card must itself remain confirmed and identity-bound. Missing/deleted/hidden cards, unchanged resources or no matching roll do not prove not-performed; no absence-based unblock or replay is offered.

A second, strictly bounded `refused-unchanged` cast decision is allowed only for a durable uncertain source whose nativeConsumed is exactly false, chatMessageUuid is null, and stored resourceAfter exists and exactly equals immutable resourceBefore. Resolve current owned caster/Actor/entry/spell identities and require the current native resource to equal that same snapshot; require no matching bridge actual-cast card as an inconsistency guard. This uses the source-proven explicit-false branch that exits before card creation, not absence alone. Null/undefined/exception consumption, resource drift, missing after facts, identity drift, matching card or read failure never qualifies. Store versioned refusal evidence and show original uncertain plus effective refused/reconciled; never rewrite source or reopen castId. No-message resolution records remain unresolved.

Inspect blocked legacy cases with actionable missing-evidence explanations. A later valid append may supersede only effective unresolved state, not erase history. Same-operation reconciliation is idempotently blocked; uncertainty in the append itself is reported without automatic retries, and a committed append with lost acknowledgement is found/read rather than duplicated.

## Required validation

Cover bounded history/status filters and hidden secrets; source records byte-for-byte preserved; resource/native-message predicates; no evidence/contradiction/legacy rejection; stale/hash/lock/session/world/auth changes; semantic original duplicates remain blocked after reconciliation; fresh Actor casts unblock only for a validated overlay; malformed/capacity/read errors fail closed; concurrent reservations/reconciliation append; before/after-commit/lost acknowledgement and no retry. Verify the UI routes through existing approval logic and source/companion schemas/discovery/docs agree. Record matching-build live acceptance separately from mocks and release publication.
